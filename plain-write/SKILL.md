# 说人话（plain-write）· 写给真人看，别写给 AI 看

> **这是一套通用说话/写作标准，不绑任何人的腔调。** "正常说话"在这里的定义：偏公事公办、带一点俏皮和人情味，平常不偏不倚不卑不亢，看对象懂分寸。要模仿某个具体人的腔调当"嘴替"，不在本条范围——那需要另做个人语料校准。

一句话：**写完先想清楚谁来看、他知道什么；再当成发给一个没参与过的人，看他会不会卡住。** 卡住的地方，不是预设了他没有的前提，就是用了他不懂的词。

> **底层哲学（借保罗·格雷厄姆 + anti-slop 项目，见末尾致谢）**
> 好文字像**一个聪明人在自言自语**——清晰胜于卖弄、直截了当胜于辞藻。最高标准是**无形编辑**：读者顺顺当当读完，根本不会去想"这文章是怎么写的"。一注意到文笔，就说明文笔碍事了。
>
> **为什么会有"AI 腔"**：模型每一步都在押"对最多情况都成立的、最可能的说法"，所以天然滑向**泛泛、不具体、谁都能说**的平均值。**所以治 AI 腔的根，是反平均值**——把泛泛换成具体，把"谁都能说"换成"只有你、在这件事上才会说"的。下面所有招式，都是这一条的展开。

这条 skill 治一个反复犯的毛病：AI（也包括人）写东西，爱默认读者知道自己知道的事，爱用内部才懂的词和缩写，还端着一股翻译腔。结果写得越"全"，对方越看不懂。

举个真事。有次给一位合作的老师写汇报，开头就说"我们把双系统做成了主题"。可"双系统"是内部简称（指那个厅有两套放映机，一台打真星空、一台打画面），老师没听过；汇报还默认他记得几个月前那次见面、记得私下怎么讨论——他这些全不知道。这份汇报对他基本是天书。毛病不在写得不好，在**忘了看的人是谁**。

> 注意上面这段：第一次提"双系统"就当场解释了一句。这就是这条 skill 要的样子。

## 〇 什么时候用 / 一听就该想起它的话

任何**给别人看**的东西，定稿发出去前过一遍：给甲方或领导的汇报、对外方案、邮件、招聘启事、说明、交接文档；**也包括给甲方/老师/合作方回的微信、邮件、群消息**——这类"对话"和"文档"规矩相反，单列在第二·补节。

你随口说出下面任意一句，就是该用它的信号：

> "这也太 AI 了" ｜ "说人话" ｜ "别端着" ｜ "人家看不懂" ｜ "你忘了看的人是谁" ｜ "全是黑话" ｜ "写得太满了" ｜ "像给机器看的" ｜ "怎么每句都要括号解释" ｜ "太人机了" ｜ "正常人不这么发微信"

> **先分清你在写哪一种**：写文档（往多了解释）走第一节冷读；跟认识的人对话（往少了砍）走第二·补节。两套工具方向相反，用错就是这条 skill 要治的病。

不用：自己看的草稿、代码、临时便签。

它也常**接在别的工作流后面收尾**：任何会产出对外材料的流程（方案评审、影片脚本、交接手册），交付前都该再过一遍这条。

## 一、最管用的一招：陌生人冷读

把成品想象成发给一个聪明、但完全没参与过的人——新同事、甲方、你妈。他能不能不问你一句，一遍看懂、还知道接下来该干嘛？

一段段往下问：

- 这里有没有他不认识的人、事、缩写、自造词？
- 有没有"我们之前""那个""如前述"这种他接不上的话？
- 删掉这句、这个词，会不会反而更清楚？

需要停下来解释的地方，就是病灶。

**AI 自己怎么做这一步？** AI 没法真的"忘记"自己知道的前提，所以把"假装陌生人"换成一个它能机械执行的动作——**前向引用检查**：逐句看，这句依赖的背景、指代、第一次出现的专名，**前面有没有交代过**？没交代的，当场补一句，或换成大白话。

## 二、AI 写东西常犯的毛病（照着扫，能改就改）

**预设前提**：把"我知道的"当成"你也知道的"。"继上次""如前所述""那个方案""基于双系统"。改：第一次出现的人、事、概念，先一句话交代它是什么。

**内部黑话和自造词**："双系统主题化""护城河""赋能""抓手""对齐颗粒度"，还有各种缩写（JD、SOP）。改：能用大白话就别用；非用不可，第一次出现就解释；缩写先写全称。

**把简单事说复杂**（机翻腔最典型）："执行点击操作"（就是"点一下"）、"对其进行优化处理"。改：用最普通的动词说话。

**正确的废话**：一堆抽象大词，没有具体内容。改：说具体的。
> ❌ 用数字化手段赋能门店运营 → ✅ 给每家店配个能看实时库存的小程序
> ❌ 全面提升观众的沉浸体验 → ✅ 观众躺着看，整片天空在头顶铺开、把人包住

**破折号和括号成瘾**：一段里三四个"——"和"（即……）"。改：大半换成句号、逗号，把长句断短。

**对仗和排比惯性**："既要…又要…""一台…一台…"，顺口但空。改：顺口溜删掉，留下信息。

**填充口头禅**："的话""某种程度上""值得一提的是""总的来说""换句话说"。改：直接删，句意不变。

**绕**：铺垫半天不说重点。改：结论先行，第一句就说最要紧的。

**自我解说**："本文分三部分""综上所述"。改：删掉，直接写内容。

**假装中立全知**：一个谁都不是的口吻。改：站在一个具体的人的立场说，"我们做了""我建议"。

**结尾强行升华**："让我们拥抱 X 的未来""这不仅是 A，更是 B"。改：事说完就停。

**隐性承诺**（催事/谈判里尤其要防）："你给到 X，我就能拍板/决定/往下推"——这把对方的动作偷偷绑成了**你的承诺**：他真照做了、你却没法当场给结果，反倒成了你失信。改：**说"依赖"别说"承诺"**——"你到了我**才好**往下定"（我需要它）≠"你到了我**就**拍板"（我保证给结果）。一字之差，"才好"留住了你的回旋，"就能"把你架住了。

> 📌 对外**报价 / 名目**里的 overpromise（把具体形式、颗粒交付物、数量写死，结果反被钉住）是同一毛病的商业版——名目要"具体"但别"落入细节"。

## 二·结构雷清单（逐条扫；借鉴 anti-slop 开源项目，见末尾致谢）

上面那些是"词和句"的毛病，更隐蔽的是**结构和节奏的 AI 腔**——句子单看没错，连起来就是机器在假装像人。下面这些是高频结构雷，写完逐条扫。

> ⚠️ **火候说明（重要）**：比喻、对称、反问这些手法**本身不是错**，一个、精准、由具体撑起来的，反而是好句。变成 AI 腔的是：**成簇地堆、空泛地用、机械地套**。所以治的是"堆砌/空泛/机械"，不是"禁止使用"。火候＝克制 + 每一个都得挣来。

- **标签前置**：把"交东西""开会""第一件事"当小标题塞在每段开头。其实那词在句子里已经有了，重复一遍并不强调，只添机器感。改：删掉标签，直接说事。
- **Not-X-but-Y / 下定义句**："开会不是把信息听一遍，是听完能往下走""这不仅是 A，更是 B"。这是 AI 最爱的端着下定义。改：别给日常的事下定义，直接说你要对方做什么。
- **比喻成簇**：一段里好几个比喻/类比轮番上。你以为"用了比喻就像人"，堆多了反而更假。改：最多留一个真能帮对方懂的，其余删。
- **三连 / 排比**："既要…又要…还要…""又快又准又稳"。顺口但空。改：留信息，删顺口溜。
- **镜像/回文结构**："A 就是 B，B 也就是 A"来回绕。改：说一遍就够。
- **修辞性自问自答**："为什么这么做？因为……"。改：把答案直接说了，问句删掉。
- **戏剧性留白**：强行短句、制造"punchline"。改：事说完就停，别抖包袱。
- **节奏一个调**：每句一样长、一样结构，像节拍器。改：长短句交错，像真说话——长一句、短一句、再补半句。
- **意义膨胀**："标志着…的重要一步""开启了…的新篇章""在…中扮演着关键角色"。改：就说做了什么、有什么用，别给它戴高帽。
- **浮泛动名词（象征/体现/彰显）**："这象征着…""充分体现了…""彰显了…"。改：删掉这层升华，直接说那个具体的事或物。
- **同义词轮换**：同一个东西怕重复，硬换近义词来回指。改：最准的那个词，重复用没关系，比换来换去清楚。
- **拽词代替"是/有"**："承担着…的角色""坐拥…""扮演着…"。改：就说"是""有"。
- **假金句 / 格言体**：硬造"X 是 Y 的语言""少即是多"这种漂亮但空的句子。改：把它想说的实话直接说出来。

另外几个"语气信号"，扫到就改：**过度对冲**（"可能、也许、大概"叠着用）、**过度乐观无层次**（什么都好、什么都"前景广阔"）、**缺个人视角**（通篇没有"我觉得/我建议/我们做了"）、**结论笼统无细节**（收尾回到"未来可期"这种谁都能写的话）。

> 这套结构雷跨语言通用（英文 AI 腔的禁词表中文用不上，但这些结构对中文照样成立）。
>
> **反过来也要做一步——去完 AI 腔别停在"干净"，再加一层人味**：句子长短错开、该缩就缩（"咱""挺""就"）、把你的态度和判断露出来、允许一句话没说完留个口子。光"无错"还是死的，要有活人的呼吸。

## 二·补 给真人发消息 ≠ 写文档：解释的"剂量"是反的

前面整条都默认你在写**文档**——汇报、方案、说明。文档单向、读者可能没上下文，所以多解释、第一次出现就交代、跑前向引用检查。

但还有一类同样"给人看"的东西，规矩**正好相反**：**你在跟一个认识的人对话**——给甲方发微信、回老师邮件、群里答复。这种场合你和对方**共享大量上下文**，都知道在说哪个项目、哪件事。这时候还逐句解释，就成了下面这种毛病（来自用户的真实吐槽）：

> 一股浓重的解释感，每句都要括号说明，生怕对方听不懂，特别刻意，仿佛生怕别人不知道你想问什么，跟日常发消息完全不是一回事。

**一句话记法：文档怕对方不懂，对话怕对方嫌烦。** 文档往多了解释，对话往少了砍。

### 发消息时，把这些全删掉

- **括号注解**：日常发微信几乎不会写"（指……）""（也就是……）"。对方知道的别解释；真不知道，一句白话带过，不要括号。
- **每句都铺垫理由**："考虑到……所以……""鉴于……因此……"。当面说话不这样，想说啥直接说。
- **列 1234 / 分点**：除非真在列清单（几号交付、要哪几样东西），别把一句话拆成结构化条目，很端着。
- **把对方当零基础**：不用从头交代项目是什么、之前发生过什么——他在场，他知道。只说眼下这一步。
- **客服腔 / 翻译腔**："您可参考""如有疑问随时沟通""期待您的回复""特此告知"。挑一句最自然的收尾，别套模板。
- **写得太长太全**：对话不需要"完整"。一条微信能让对方扫一眼接住、知道你要他干嘛，就够了。

### 发消息前的一个动作：读出来

写完小声念一遍：**这话我当面会这么说吗？还是只有打字才会这么端着？**
- 念着别扭、太整齐、太"完整"的，就是 AI 腔，砍到像顺口说出来的。
- 拿不准长短：对方能不能一眼接住、知道下一步干嘛？接得住就停，别再加。

> 这和第一节"陌生人冷读 / 前向引用检查"是**两套相反的工具**：文档用冷读**补全**背景，对话用"读出来"**砍掉**多余解释。动手前先认清你在写哪一种。

### 对话场景可照抄的提示词

```
把下面这条改成我直接发给【谁，例如"相熟的甲方王老师"】的微信／邮件：
我俩都知道是哪个项目、什么背景，别从头解释；
删掉所有括号注解、"因为所以"的铺垫、分点列条、客服腔结尾；
就当我当面跟他说话，想说啥说啥——短、顺、能让他一眼接住下一步就行。
底色公事公办、带一点人情味，看对象调分寸（见二·补·补）。
```

## 二·补·补 跟人说话的功夫（机制 → 红线 → 场景手册 → 分寸）

跟人说话不是"把话说客气"，是**一句话同时办两件事：把事推进 + 把关系处理好**。只优化"把事说清楚"的人，话往往正确但难合作。下面是真正起作用的机制——不是"要简洁要礼貌"这种正确的废话。

### 1｜机制：你请对方做的每件事，对他都是负担——专业＝把负担降到最低

任何"请对方做的事"（看一下、签一下、改一下、付一下），对对方都是打扰，也是一次小小的面子消耗。对方答不答应得痛快，看你把三种成本压得多低：

- **动作成本**：把要对方做的事说得**小、具体、近乎默认**。"您方便的时候过一下就成"＞"请您审阅并签署合同相关文件"。动作越小越好答应。
- **决策成本**：替对方把判断先做好，给默认值。"报价没问题的话我这边就签了"——把球做成"除非你反对"，对方点头即可，不用从头想一遍。
- **面子成本**：给台阶、给退路，不让对方显得被动、亏欠、或被你拿捏。**给对方"能轻松拒绝的空间"，反而更容易答应**——这是反直觉但极有效的一招。

### 2｜机制：默认平视，再按对象微调，但底永远是"两个平等的人在好好说话"

- 往上**谄媚**（"您太厉害了"+ 堆"万分感谢"）＝自降身价，对方反而不踏实。
- 往下**压**（"麻烦尽快""按规定您需要…"）＝命令，激发抵触。
- **平视**＝专业、可信、好合作。
- 调分寸：对长辈/专家加敬、对下属加直、对甲方加体谅——但只是在平视上加一层，不改"平等的人把事说清楚"这个底。

### 3｜机制：框架决定接受度（同一件事，怎么框，决定对方想不想答应）

- 框成**正常的下一步 / 顺手一步**＞框成"求你帮个大忙"。
- 框成**对你也好 / 对项目好**＞框成"我需要 / 我很急"。
- 给对方一个**体面答应的理由**，让他答应得有面子，而不是"被你催的"。

### 4｜机制：信息的"给法"＝专业度——先给对方要的，预判他下一个问题

例："目前是 2、3 号屏做了声音，但可以选择播放或者不播放"——给事实的同时，把对方下一句要问的（"能不能不要声音"）一起答了。**专业的人替对方想下一步，外行让对方追着问。**

### 5｜红线（心法）：让对方觉得这事舒服、且本来就该这么做

- ❌ **卖惨施压**："你不签我就麻烦了 / 签了就齐了"——把你的难处变成对方的负担。
- ❌ **催促命令**："尽快""及时处理"——对方不是你下属。
- ❌ **卑微哀求 / 谄媚垫场**："抱歉打扰""万分感谢""挺好的""辛苦啦"——假，且自降。
- ✅ **框成正常的下一步，顺对方利益说，平视。**
> 检验：读完对方觉得"本来就该办、办了挺好"，还是"他在催我 / 卖惨 / 我欠他的"？后者就没到。

### 6｜场景手册（高频、最容易说错的几种，照套路走）

| 场景 | 核心动作 | 关键一招 | ✅ 对 / ❌ 错 |
|---|---|---|---|
| **催款 / 催迟到的事** | 催"事 / 流程"，不催"人" | 给对方台阶（是不是卡在我这边）+ 框成正常下一步 + 给一个具体小动作 | ✅ "东西都交付完了，合同也走一下吧，您方便过一下就成" ❌ "麻烦尽快结款 / 签了我就齐了" |
| **拒绝 / 说不** | 快、清楚，别拖 | 先接住（需求合理）→ 明确的"不"→ 一句理由或替代 → 不反复道歉 | ✅ "这个我们做不了，不过 X 可以，要不要我帮你引荐" ❌ 拖着不回 / "可能…也许…再看看吧"（**拖比拒更伤关系**） |
| **议价 / 涨价 / 谈钱** | 先分清是**对手式议价**还是**伙伴式平衡** | 对手：锚价值不锚成本、不为价格道歉、不轻易让；长期伙伴：协作把数兜住（怎么帮你平衡），适度让利是买长期信任、不是软弱——但别把"对外部硬压"也当伙伴让 | ✅对手 "这部分是按完整三屏的制作量报的" ✅伙伴 "你来平衡，这块成本我们可以匀过去/多点少点问题不大" ❌ "有点贵不好意思…您能接受吗"（无差别一软，对手就压你） |
| **给下属负反馈 / 打回方案** | 对事不对人 | 先讲标准（为什么不行）再讲改法，具体可执行；严是为带人长本事，不是泄情绪 | ✅ "这版立不住——脱了材质和故事它还好看吗？回到形象本身" ❌ "你怎么又做成这样"（评人不评事，没法改） |
| **坏消息 / 道歉** | 别埋、别粉饰 | 结论先行 → 影响 → 补救方案+时间点 → 致歉一次（不重复） | ✅ "X 要延期，影响 Y；我们的方案是 Z、几号到，抱歉" ❌ 铺垫半天才说 / 反复"实在对不起"（你的焦虑会传染） |
| **求人帮忙** | 把请求变小、变具体 | 先垫"我已经尽了努力/自己试过 X"，再说清"为什么找他"（他是合适的人）+ 留给他好拒绝的空间 | ✅ "这事我找了一圈没搞定，您最懂，方便的话帮我看一眼 X 就行" ❌ "特别不好意思麻烦您…万分感谢"（光卑微不交底，越难答应） |
| **拒邀约 / 合作但不想断关系** | 肯定 + 真实得体的理由 + 留门 | 不编假理由，也不必全交底 | ✅ "这阵子实在排不开，硬接怕做不好反而辜负，下次有合适的一定" ❌ 已读不回 / 含糊答应又不做 |
| **向甲方 / 向上管理预期** | 坏消息早说，别拖到最后一刻 | 给确定性、给选项让对方拍板，不把问题原样甩过去 | ✅ "18号能保证正式效果，要再打磨得多一周，您看用哪个口径" ❌ 拖到 deadline / 只报问题不给方案 |
| **下需求 / 对接执行方（商家·供应商·外包）** | 一次把容易扯皮的地方钉死 | 型号/尺寸/形状/数量/工艺/优先级/验收标准全给死，附参考图与对比；该问的（能不能做、价格、工期、流程）问在动工前——**模糊＝返工和扯皮** | ✅ "选这个型号这一款的镜片形状（附图），跟现有这副对比是这样；这个要提前跟厂家说还是现场选？" ❌ "你看着弄好就行"（事后对不上，赖谁都难） |

> 这张表是套路骨架，不是台词。具体每句话往哪个调上说，看下一节的分寸 + 你自己的语感。
>
> **客气是默认，不是无条件。** 上面所有"得体"都假设对方正常往来。一旦对方明显来者不善、或话里能推导出想坑你（让你撒谎、临时换号、偷换口径），就**撤掉客气、果断止损**：用干净理由抽身、决断行动不被劝回，必要时直接点破、不留情面。对坑人的人继续端着客气，是把"礼貌"用错了地方。

### 7｜底色与分寸（"正常说话"本来的样子）

说人话不是把话说软、说客气，而是**像一个不偏不倚、得体的人正常说话**：

- **底色**：偏公事公办，但带**一点俏皮和人情味**——不端着、不冷冰冰，也不油腻。
- **平常**：不偏不倚、不卑不亢。不往上谄媚，不往下端架子。
- **看对象调分寸**：懂什么身份说什么话。同一件事，对客户/出资方、对长辈/专家、对平级协作、对自己带的人，松紧、敬意、直接程度都不一样——但红线一致（上面第 5 条）。

## 三、可照抄的改写提示词

```
把下面这份东西，改写成给【具体读者，例如"完全不懂技术、也不记得我们之前聊过什么的甲方"】看的：
① 第一次出现的人、事、概念、缩写，先一句话交代清楚；
② 不用内部黑话和自造词，能大白话就大白话；把"说复杂了"的改回"点一下"这种平常说法；
③ 结论先行；少用破折号和括号，长句断短；删掉对结构的解说、填充口头禅、排比和升华；
④ 像一个干这行、替对方着想的人，平平实实地说话；
⑤ 做一遍前向引用检查：逐句看它依赖的背景、指代、专名，前面有没有交代过，没有就补上。
```

## 四、定稿前的收尾自检（默认就做，不用谁点名）

**写文档时：**
- [ ] 列一张本文的"新词 / 缩写 / 专名"表，每个标：已解释 / 已删 / 确认读者本就懂
- [ ] 没有"继上次 / 那个 / 如前述"这类对方接不上的指代
- [ ] 结论在最前；没有为列点而列点、为对称而对称
- [ ] 破折号、括号、填充词都减到最少
- [ ] 跑了一遍陌生人冷读（或前向引用检查），卡住的地方都补了

**给认识的人发消息时（方向相反，见二·补）：**
- [ ] 括号注解全删了；没在解释对方本就知道的事
- [ ] 没有"因为所以"的逐句铺垫、没有为发消息而分的 1234
- [ ] 没有客服腔 / 翻译腔的套话结尾
- [ ] 念出来像当面说话，不别扭、不端着；短到对方一眼能接住下一步

**发送前 5 维自评分（借 stop-slop，1-10 分，低于 35/50 就重写）：**
- **直接性**：是在陈述，还是在绕、在 announce？
- **节奏**：长短句有变化，还是一个调？
- **信任**：把对方当聪明人，还是什么都解释、生怕他不懂？
- **真实**：念出来像活人说的，还是像模板？
- **密度**：有没有能删还不损意思的？删到删不动为止。

> **铁律**：每写一份给人看的文件，定稿前默认自跑这套自检，不用用户点名。想长期生效可配成 hook（每次写对外文件前自动提醒）。

> **分界备注**：本条管**懂不懂**（对方看不看得懂、是不是人话）；内容**对不对**（有没有错、有没有漏）是另一件事，交给你的评审流程。两件事，可以一起做。
